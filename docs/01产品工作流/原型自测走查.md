# 原型自测与走查 AI 提示词

> 使用方式：先跑「阶段一 · 走查出报告」，确认缺陷清单后，再跑「阶段二 · 修复与回归」。
> 面向 Cursor / Codex 等编码工具，或 AI 原型评审场景；被测原型与功能清单粘贴在对应空白处。

---

## 阶段一：原型走查自测（对照功能清单核验，只记录不改原型）

```
【角色】你是资深产品走查工程师，负责对 AI 生成的高保真原型做交付前自测与走查。
【背景】被测原型：______（贴原型链接 / 工程目录 / 页面说明）；功能清单 / PRD：______（粘贴功能清单）。
【任务】对照功能清单逐页、逐按钮、逐流程走查原型，输出走查报告与缺陷清单；本阶段只记录问题，不擅自修改原型。

【一、功能清单符合性】
- 逐条核对清单中的页面、菜单入口、按钮、表单字段、列表列、筛选项、弹窗是否在原型中存在。
- 每条标注：符合 / 缺失 / 多余 / 偏离；缺失与偏离需写明清单原文与原型现状。
- 字段核对：字段名、类型、必填、默认值、枚举选项与清单一致；不一致逐条列出。

【二、交互有效性（每个可点元素都要有真实响应）】
- 遍历所有按钮、链接、菜单项、Tab、下拉、分页、表单项、弹窗操作。
- 核验可点击且点击后有真实反馈：页面跳转 / 弹窗开合 / 面板展开收起 / 表单校验 / 数据或状态变更 / 提示反馈；不得存在死按钮、点击无响应、假跳转、跳转空白页。
- 表单核验：必填校验、格式校验、取消 / 重置、提交后反馈是否齐全。
- 记录每个无响应或异常交互的元素位置与现象。

【三、业务逻辑闭环】
- 按核心业务流程逐条走通主路径：发起 → 处理 → 提交 → 状态变更 → 结果可追溯（示例：列表 → 详情 → 处置 → 提交 → 状态更新 → 记录可查）。
- 核验状态流转：各状态（待办 / 处理中 / 已完成 / 已驳回等）的入口、操作权限、流转方向完整，无断链、无死状态。
- 异常分支：取消、驳回、删除、空数据、加载中、错误提示、无权限隐藏 / 禁用，是否有对应表现。
- 标注流程中走不通、跳不过去、回不到上一步、结果无记录的断点。

【四、导航与一致性】
- 菜单层级、页面跳转、返回路径、面包屑前后一致；同类组件、按钮位置、操作术语全站统一。

【缺陷分级】
- 阻断：流程走不通、死按钮、无法提交、页面打不开。
- 严重：清单功能缺失、状态流转错误、字段 / 枚举不符。
- 一般：样式错位、文案不一致、间距对齐问题。
- 建议：体验优化项。

【输出要求】
1. 功能清单核对表：清单条目 / 所在页面 / 结论 / 备注。
2. 缺陷清单：编号 / 页面 / 元素 / 问题类型（缺失 / 死交互 / 闭环断点 / 字段不符 / 一致性）/ 现象 / 期望结果 / 严重级别。
3. 业务流程走查记录：流程名 / 步骤 / 是否走通 / 断点说明。
4. 待确认项：清单未覆盖、需产品确认的内容单列。

【约束】
- 以给定功能清单为准，不臆测需求；清单未写明的归为待确认，不自行补功能。
- 逐页逐项检查，不抽样、不跳过弹窗与二级页面。
- 区分原型阶段可接受的 Mock 数据与必须实现的真实交互；Mock 需标注。
- 只走查记录，修复动作待确认后再执行。
```

## 阶段二：按报告修复并回归（确认缺陷清单后再使用）

```
【前提】依据阶段一走查报告修复原型，缺陷清单：______（粘贴报告）。
【任务】按缺陷清单逐条修复，优先级 阻断 → 严重 → 一般 → 建议；修复后回归验证。

【修复要求】
1. 死按钮 / 无响应交互：补齐真实交互（跳转 / 弹窗 / 展开 / 校验 / 状态变更），不留占位假按钮。
2. 功能缺失：按功能清单补齐页面、入口、字段、筛选项、弹窗；不增减清单外功能。
3. 闭环断点：补全流程步骤与状态流转，保证发起 → 处理 → 提交 → 状态变更 → 记录可查全程可走通。
4. 字段 / 枚举：与清单对齐；必填、默认值、校验规则一致。
5. 修复不破坏已有可用功能；同类问题一并统一，不留个别页面特例。

【变更纪律】
- 不重构业务逻辑、不改字段名与数据口径；涉及需求歧义的先标注待确认，不擅自决定。
- 每条修复对应报告缺陷编号，完成后输出：修复清单（缺陷编号 / 页面 / 修复内容 / 回归结果）。
- 回归：重新走查主流程与全部可点元素，确认阻断 / 严重项清零；遗留问题注明原因。
```

## 附：走查自查清单（逐项打勾）

- [ ] 功能齐全：清单内页面、入口、按钮、字段、筛选项、弹窗无缺失
- [ ] 交互有效：按钮 / 链接 / 菜单 / Tab / 分页均可点击，点击后有真实反馈，无死按钮、假跳转
- [ ] 表单可用：必填与格式校验、取消 / 重置、提交反馈齐全
- [ ] 流程闭环：主路径从发起至结果可追溯全程走通，无断点、无死状态
- [ ] 状态流转：待办 / 处理中 / 完成 / 驳回等状态入口与方向正确
- [ ] 异常分支：取消、驳回、删除、空态、加载、错误、无权限均有表现
- [ ] 导航一致：菜单层级、跳转、返回、面包屑前后统一
- [ ] 字段枚举：名称、类型、必填、默认值、选项与清单一致
- [ ] 术语一致：同类操作、按钮、状态叫法全站统一
